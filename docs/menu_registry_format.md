# Формат файла для залива меню

Файл заливается суперадмином на странице «Вкусная тетрадь» → «Загрузка меню файлом»
(`POST /api/v1/menu/admin/import`). Разбор — [`backend/app/services/menu_import.py`](../backend/app/services/menu_import.py),
тесты формата — [`backend/tests/test_menu_import_parser.py`](../backend/tests/test_menu_import_parser.py).

## Что заливать

Два варианта:

- **`.xlsx`** — только текст. Фото блюд не будет; картинку ингредиентов и озвучку
  сервер сгенерирует сам.
- **`.zip`** — тот же реестр `.xlsx` плюс папки с медиа. Пути в колонках реестра
  резолвятся внутри архива.

Zip нужен потому, что через браузер нельзя передать «относительные пути с диска»:
если в реестре написано `dish_photos/001_Плов.png`, сам файл должен приехать вместе
с реестром.

```
меню_ЖУ.zip
├── реестр.xlsx
├── dish_photos/        ← фото готового блюда
├── images/             ← картинка ингредиентов (если уже есть)
└── audio/              ← озвучка (если уже записана)
```

Потолок на загрузку — 1 ГБ. Файл пишется на диск потоком, целиком в память не читается.

## Колонки реестра

Берётся первый лист книги. Первая строка — заголовки.

| Колонка | Куда попадает | Обязательна |
|---|---|---|
| `№` | никуда, для человека | нет |
| `Раздел` | категория меню, создаётся при отсутствии | нет |
| `Блюдо` | название | **да** |
| `Ингредиенты (подписи)` | состав блюда + основа промпта для картинки | нет |
| `Текст озвучки` | описание блюда и текст для TTS | нет |
| `Фото блюда (файл)` | путь внутри архива | нет |
| `Картинка ингредиентов (файл)` | путь внутри архива | нет |
| `Озвучка (файл)` | путь внутри архива | нет |
| `Цена` | `price_rubles` | нет |

Колонки ищутся **по заголовку, а не по номеру** — их можно двигать и дописывать свои.
Совпадение по подстроке без учёта регистра, поэтому «Раздел» и «Категория» равноценны,
как и «Текст озвучки» с «Описание».

Две ловушки, которые парсер разводит специально:

- `Ингредиенты (подписи)` — это текст, а `Картинка ингредиентов (файл)` — путь. Слово
  «ингредиент» есть в обеих; колонка со словом «файл» или «картинка» никогда не попадёт
  в состав блюда.
- Колонки со ссылками на creations (`Картинка ингред. (Magnific)`, `Озвучка (Magnific)`)
  игнорируются — там лежит гиперссылка «Открыть», а не файл.

Если ни один заголовок не опознан, парсер откатывается на канонический порядок колонок
из таблицы выше.

Пустой ячейкой считаются также тире `—`, `–` и `-`. Строка без названия блюда молча
пропускается — это разделитель, а не ошибка.

## Что генерируется, а что берётся готовым

Галочки в форме залива включают три стадии независимо. Генерируется **только то, чего
нет в файле**: если картинка ингредиентов или озвучка приехали в архиве, провайдеру за
них не платим.

| Стадия | Чем | Источник |
|---|---|---|
| `image` | Magnific (`POST /v1/ai/mystic`) | промпт из названия блюда и состава |
| `audio` | провайдер из `TTS_PROVIDER` | колонка «Текст озвучки» (или состав, если её нет) |
| `video` | ffmpeg, локально | картинка ингредиентов + озвучка |

У Magnific в публичном REST API **нет text-to-speech** — только музыка, звуковые эффекты
и audio-isolation. Их собственный TTS внутри работает на ElevenLabs, поэтому за озвучкой
ходим к ElevenLabs напрямую: движок и голоса те же. Ключи — `MAGNIFIC_API_KEY` и
`ELEVENLABS_API_KEY`, см. `backend/.env.example`.

Две вещи, на которых легко обжечься:

- `MAGNIFIC_IMAGE_MODEL` — это **стиль внутри Mystic**, а не название эндпоинта. API
  принимает только `realism`, `fluid`, `zen`, `flexible`, `super_real`,
  `editorial_portraits`; значение `mystic` он отвергает. Для раскладки продуктов нужен
  `realism`.
- **ElevenLabs закрыт для российских IP.** На запрос он отвечает не ошибкой, а `302` на
  статью про страновые ограничения. Поэтому с боевого сервера стадия `audio` через него
  не работает, и `synthesize_speech` специально ловит редирект: иначе HTML-страница
  справки молча легла бы на диск под именем `.mp3`.

Из-за этого провайдер озвучки выбирается настройкой `TTS_PROVIDER`:

| значение | ключи | когда брать |
|---|---|---|
| `elevenlabs` | `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID` | если у сервера есть выход за пределы РФ |
| `yandex` | `YANDEX_TTS_API_KEY`, опционально `YANDEX_TTS_FOLDER_ID` | по умолчанию для сервера в России |

Голоса ElevenLabs, кстати, входят в подписку Magnific (в каталоге семь русских), но
доступны только из веба и по MCP — в REST API их не вывели, поэтому серверу этот путь
закрыт. Смена провайдера — это одна строка в `.env`, пайплайн от неё не зависит.

Проверить настройку до залива — `backend/scripts/check_generation.py`:

```
docker compose exec backend python scripts/check_generation.py          # бесплатные пробы ключей
docker compose exec backend python scripts/check_generation.py --full   # реальная генерация, тратит кредиты
```

Кредиты API списываются с **общего баланса организации** — тот же счётчик, что и в вебе.
Отдельного пула у API нет; оговорка в доке про «Unlimited» касается только безлимитных
тарифов, а не обычного остатка кредитов.

Без ключей текст и фото из архива заезжают всё равно, а стадии генерации падают с
понятной ошибкой и видны в отчёте — их можно повторить кнопкой «Повторить упавшие»,
не заливая файл заново.

## Повторный залив

Блюдо ищется по названию **в пределах выбранного ресторана**: одноимённый «Плов» в другой
точке — другое блюдо со своим фото, перетирать его нельзя. Найденное обновляется, новое
создаётся. Пустые ячейки не затирают уже заполненные поля, а медиа из архива перекрывает
старое — раз файл положили в архив, хотят именно его.

## Проверка перед заливом

Кнопка «Проверить файл» шлёт тот же запрос с `dry_run=true`: ничего не пишет и возвращает
план — сколько блюд создастся, сколько обновится, какие разделы появятся, что придётся
генерировать и в каких строках медиа не нашлось.

Там же проверяются ключи провайдеров. Если генерация заказана галкой, а ключа на сервере
нет (`MAGNIFIC_API_KEY` для картинок, `YANDEX_TTS_API_KEY` либо `ELEVENLABS_API_KEY` — смотря
что стоит в `TTS_PROVIDER`), под кнопками появляется предупреждение вида «генерация озвучки
запущена, но ключ не задан». Залив при этом не блокируется: текст и медиа из файла заезжают,
падают только задания генерации. После того как ключ пропишут в `.env` и перезапустят
контейнер, эти задания перезапускаются кнопкой «Повторить упавшие» у нужного залива.
