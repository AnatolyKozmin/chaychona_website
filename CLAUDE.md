# CLAUDE.md

Платформа обучения персонала ресторанной сети «Чайхона №1»: курсы, тесты, чек-листы смен, меню («Вкусная тетрадь»), управление пользователями/ролями.

Стек: FastAPI + PostgreSQL + SQLAlchemy (backend/) / Vue 3 + Vite + Pinia + Vue Router + TS (frontend/). Деплой — Docker Compose.

Подробная архитектура (модели, API-роуты, frontend-страницы, конфиг, особенности): см. **[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)**.
Запуск/тесты/команды: см. **[README.md](README.md)**.
Формат импорта тестов из Word: **[docs/word_tests_format.md](docs/word_tests_format.md)**.
Формат файла для залива меню: **[docs/menu_registry_format.md](docs/menu_registry_format.md)**.

## Быстрые факты, которые легко упустить

- Нет Alembic — миграции схемы — это idempotent raw SQL в `backend/app/main.py::_run_startup`, выполняется при каждом старте backend. Новые изменения схемы дописывать туда же.
- Роли: `superadmin` / `admin` / `learner` (у learner отдельное поле `job_title` для трека контента). См. `backend/app/models/user.py`.
- Регистрация — заявочная (`registration_requests`), одобряет superadmin.
- JWT access+refresh, frontend (`frontend/src/api/client.ts`) авто-рефрешит токен по 401.
- Контент (курсы/тесты/чек-листы) таргетируется через `restaurant_id` + `job_title_id`.

## Мобильный сценарий (приложение с рабочего стола)

Основной пользователь — официант с телефоном в зале, приложение ставится иконкой на рабочий стол. Отсюда несколько вещей, которые легко сломать не заметив:

- PWA собрана вручную, без плагинов: `frontend/public/manifest.webmanifest`, иконки в `frontend/public/icons/`, `frontend/public/sw.js`. Регистрация — в `frontend/src/main.ts`, **только при `import.meta.env.PROD`** (в dev перехватывал бы HMR). Service worker кэширует исключительно свою статику; ответы API персональные и ходят под JWT — их не кэшируем никогда. При правках `sw.js` поднимать `VERSION` внутри файла, иначе старые кэши не подчистятся.
- `nginx.conf` держит `Cache-Control: no-cache` на `sw.js` и манифесте. Без этого после деплоя пользователи остаются на старой версии.
- В `index.html` у viewport стоит `viewport-fit=cover`. Без него `env(safe-area-inset-*)` всегда 0 и нижняя панель уезжает под домашнюю полоску iPhone.
- Скругления сняты по всей вёрстке через токен `--radius` в начале `main.css` — менять только там, отдельные `border-radius` в файле не прописывать.
- Поля ввода на мобильных форсированы в 16px: меньший размер вызывает автозум iOS Safari при фокусе.
- Презентации в стандартах — это **картинки, а не PDF**: файл режется на слайды при заливке (`backend/app/services/presentation.py`, `POST /courses/admin/presentation`), сотрудник листает их свайпом, тап открывает слайд на весь экран. Принимается только PDF; `.pptx` потребовал бы LibreOffice в образе. Блок с колодой нельзя отметить изученным, не долистав до последнего слайда.
- Сохранение стандарта **пересоздаёт все блоки** (`_replace_blocks` в `courses.py`), поэтому форма админки обязана слать обратно всё содержимое блока — и `image_path`, и `slides`. Что не отправлено, то удалится.
- Разметка аллергенов в составе блюда — `frontend/src/lib/allergens.ts` (по ключевым словам, на клиенте; в базе поля аллергенов нет). Один ингредиент может нести несколько аллергенов сразу. Это подсказка официанту, а не гарантия: список ключевых слов должен проверять шеф-повар.
- Меню ресторана «Вкусная тетрадь» грузится целиком страницами по 100 и фильтруется в памяти — поиск идёт по названию и составу без запросов к API.
- Админка меню (категории, ветки, позиции, залив файлом) живёт **внутри** `TastyNotebookView.vue` под `isSuperadmin`, отдельной страницы и роута у неё нет — её легко не заметить, глядя только в роутер.
- Очередь `menu_dish_video_jobs` теперь трёхвидовая (`kind` = `image` / `audio` / `video`), имя таблицы историческое. Видео создаётся в статусе `blocked` и ждёт свои картинку и озвучку; разблокирует его сам воркер. Класс — `MenuDishMediaJob`, `MenuDishVideoJob` оставлен алиасом.
- У Magnific в REST API **нет TTS** — только музыка, SFX и audio-isolation. Картинки берём у Magnific (`/v1/ai/mystic`), озвучку — напрямую у ElevenLabs (их же движок внутри Magnific). Два разных ключа: `MAGNIFIC_API_KEY` и `ELEVENLABS_API_KEY`. MCP-инструмент `audio_tts` ходит во внутренний бэкенд magnific.com и серверу недоступен — на него закладываться нельзя.
- `MAGNIFIC_IMAGE_MODEL` — это стиль **внутри** Mystic, а не имя эндпоинта. Валидны только `realism` / `fluid` / `zen` / `flexible` / `super_real` / `editorial_portraits`; значение `mystic` API отвергает.
- **ElevenLabs недоступен с российских IP**: отдаёт `302` на статью про страновые ограничения, а не ошибку. 302 < 400, поэтому наивная проверка `status_code >= 400` пропустила бы HTML на диск под именем `.mp3` — в `synthesize_speech` стоит явная защита от редиректа и от неаудийного content-type.
- ElevenLabs **есть в подписке Magnific** (в каталоге 7 русских голосов, списываются те же кредиты), но только через веб и MCP — в REST его не вывели. Серверу этот путь недоступен, поэтому провайдер озвучки выбирается настройкой `TTS_PROVIDER` = `elevenlabs` | `yandex`; реализации — `_speak_elevenlabs` / `_speak_yandex` в `generation.py`. Ветка Yandex написана по документированной форме API, но на живом ключе ещё не проверялась.
- Кредиты API списываются с **общего баланса организации**, отдельного пула у API нет. Оговорка в доке Magnific про «Unlimited» относится только к безлимитным тарифам, а не к обычному остатку.
- Перед заливом реестра настройку генерации проверяет `backend/scripts/check_generation.py` — без флагов делает бесплатные пробы ключей, с `--full` реально генерирует одну картинку и одну озвучку.
